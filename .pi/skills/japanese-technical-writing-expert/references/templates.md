# 文書テンプレート集

各テンプレートはそのままコピーして使う。不要なセクションは削除する。

---

## 技術メモ・調査ノート

```markdown
# {タイトル}

> **対象:** {読者・チーム}
> **作成:** {日付}
> **ステータス:** {Draft / Review / Final}

## 結論

{1〜3行で要点を先出し。読んで分からなければここを読めば分かる状態にする。}

## 背景・経緯

{なぜこのメモが必要になったか。前提知識・文脈を簡潔に。}

## 調査内容

### {サブトピック1}

{内容}

### {サブトピック2}

{内容}

## わかったこと

- {事実1}
- {事実2}

## 未解決・要確認

- [ ] {確認事項1}（担当: {名前}）
- [ ] {確認事項2}

## 参考リンク

[1]: {URL} "{サイト名}"
```

## 手順書・操作マニュアル

```markdown
# {機能名 / ツール名}: 操作手順

> **対象環境:** {OS / バージョン等}
> **前提:** {必要な権限・設定など}
> **所要時間:** {目安}

## 概要

{何のための手順か。1〜2行で。}

## 事前準備

- {必要なツール・権限・情報}
- {確認すべき事項}

## 手順

1. {ステップ1}

   ```bash
   {コマンド例}
   ```

2. {ステップ2}

   {補足説明があればここに。}

3. {ステップ3}

## 確認方法

{手順完了後、何を確認すれば成功か。}

```bash
{確認コマンド例}
```

期待する出力:
```
{期待値}
```

## トラブルシューティング

### {エラー名・症状}

**原因:** {原因の説明}
**対処:** {対処手順}

## 注意点

- {注意事項1}
- {注意事項2}

## 参考リンク

[1]: {URL} "{サイト名}"
```

## 概要

{何が起きたか。1〜2行で。}

## タイムライン

| 時刻 | 内容 |
|---|---|
| HH:MM | {出来事} |
| HH:MM | {出来事} |
| HH:MM | 復旧確認 |

{技術的な根本原因を具体的に記述。推測の場合は明示する。}

## 影響

- {影響1（具体的な数値を添える）}
- {影響2}

## 対応内容

1. {実施した対応1}
2. {実施した対応2}

## 再発防止策

| 対策 | 担当 | 期限 | 優先度 |
|---|---|---|---|
| {対策内容} | {担当者} | {日付} | 高 / 中 / 低 |

## 学び

- {今回得た教訓}
