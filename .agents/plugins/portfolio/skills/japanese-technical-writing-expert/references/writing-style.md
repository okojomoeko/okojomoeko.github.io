# 日本語 Markdown 文体・表記リファレンス

> このファイルはAIが文体判断する際の静的リファレンス。
> 根拠: JTF日本語標準スタイルガイド / textlint-rule-preset-ja-technical-writing / SmartHR Design System

---

## 文体の基本

### 文末スタイル

| 場所 | 推奨スタイル | 例 |
|---|---|---|
| 本文（ですます） | 〜します / 〜です | 設定を変更します。 |
| 本文（である） | 〜する / 〜である | 設定を変更する。 |
| 箇条書き | 体言止め | 設定の変更 |
| 見出し | 体言止め・名詞句 | ## 設定手順 |
| 注意・警告 | 体言止め or 命令形 | 必ず確認する |

**ルール:**
- です/ます調とである調は文書内で統一する。
- 箇条書きは体言止めを基本とし、混在は許容するが揃えるほうが望ましい。
- 同じ語尾の連続（〜します。〜します。）を避ける。

### 1文の長さ

- 目安: **句点区切りで80字以内**
- 読点（、）: **1文に4個まで**
- 超える場合: 文を分割するか、箇条書きに変換する。

```
❌ この機能は、設定画面から、各項目を確認した上で、保存ボタンをクリックすることで、変更が反映されます。
✅ 設定画面から各項目を確認する。保存ボタンをクリックすると変更が反映される。
```

### 一文一義

- 1文に盛り込む情報は1つ。
- 「〜で、〜で、〜する」は分割する。
- 逆接の「が」の多用を避ける（「しかし」に言い換えるか文を分割）。

## 冗長表現・言い換え一覧

| 冗長表現 | 推奨表現 |
|---|---|
| することができる | できる |
| を行う | する |
| においては | では |
| に関して / に関しては | について |
| 以降 | から |
| 〜の方 | 〜 |
| 〜という形で | 〜で / 〜として |
| 〜になります | 〜です |
| 〜と思います | 〜です / 〜と考える |
| 〜していただく | 〜する |
| 各〜ごと | 各〜 / 〜ごと（どちらか一方）|
| まず最初に | まず / 最初に（どちらか一方）|
| 〜のほうが | 〜が |
| 〜かもしれません | 〜の可能性がある |

## 数値・数字

| ルール | 例 |
|---|---|
| 数量・測定値は算用数字 | 3件、120秒、v2.0 |
| 慣用句・副詞・固有名詞は漢数字可 | 一般的に、三日間、四捨五入 |
| 桁数が多い場合はカンマ区切り | 1,000件、10,000レコード |
| 単位は数字に直接付ける | 5GB、100ms、3台 |

## カタカナ表記

### 長音ルール（JTF準拠）

末尾の長音は**省略しない**。

| 省略形（NG） | 正しい表記 |
|---|---|
| サーバ | サーバー |
| フォルダ | フォルダー |
| ユーザ | ユーザー |
| コンテナ | コンテナー |
| パラメータ | パラメーター |
| エラー | エラー（そのまま） |

**例外:** 固有名詞・商標はそのままの表記に従う（Docker、Kubernetes 等）。

### 外来語の統一

表記ゆれを防ぐために文書内で統一する。

| NG（混在） | OK（統一） |
|---|---|
| インストール / インストール | どちらかに統一 |
| ログイン / ログイン / サインイン | 文書内で1つに統一 |
| リポジトリ / レポジトリ | リポジトリ（一般的） |

## スペーシング

### 半角英数字と日本語の間

スペースは**入れない**（SmartHR / 一般的な日本語技術文書準拠）。

```
❌ API の仕様を確認する。
✅ APIの仕様を確認する。

❌ v2.0 に対応している。
✅ v2.0に対応している。
```

**例外:** コード・コマンド内はそのままの表記を保持。

## 事実・推測・断定の使い分け

| 確度 | 表現例 |
|---|---|
| 確定事実 | 〜である / 〜する / 〜した |
| 高確度の推測 | 〜と考えられる / 〜とみられる |
| 低確度の推測 | 〜の可能性がある / 〜かもしれない |
| 注意・警告 | 〜に注意する / 〜しないこと |
| 未確認事項 | 要確認: 〜 / TBD |

## 情報の分類

### 決定・未決の明示

```markdown
## 決定事項
- 認証方式: JWT
- デプロイ先: AWS Tokyo region

## 未決事項
- [ ] キャッシュ戦略（要検討）
- [ ] SLOの数値（PdMと要確認）
```

### 前提・制約の明示

```markdown
> **前提:** この手順は Ubuntu 22.04 LTS 環境を想定しています。

> **制約:** root権限が必要です。
```

## 見出しの書き方

- 見出しだけで役割が分かるようにする。
- 名詞句・体言止めを基本とする。
- 動詞句は手順・操作の場合のみ許容。

```
❌ ## 設定について説明します
✅ ## 設定手順

❌ ## まとめ（抽象的すぎる）
✅ ## 設計上の制約まとめ
```

---

## リンク表記ルール

本文中に生URLを書かない。参照リンク形式に統一する。

```markdown
<!-- 本文中 -->
詳細は [公式ドキュメント][1] を参照。

<!-- 末尾 -->
## 参考リンク

[1]: https://example.com/docs "公式ドキュメント"
[2]: https://github.com/example/repo "GitHub リポジトリ"
```

**ルール:**
- 同じURLには同じ番号を使う。
- リンクテキストは「こちら」「クリック」を使わない。内容を示す語句にする。
- 末尾の `## 参考リンク` セクションに集約する。

## AIっぽい表現の回避

> 参考: textlint-rule-preset-ai-writing (2025)

避けるべきパターン:

| AIっぽい表現 | 自然な表現 |
|---|---|
| 〜という点において重要です | 〜が重要 |
| 〜を考慮することが必要です | 〜を考慮する |
| 〜という観点から | 〜の観点で |
| 〜となっております | 〜です |
| 〜させていただきます | 〜します |
| 非常に重要な〜 | 重要な〜 |
| 〜することが可能です | 〜できる |
| 〜に他なりません | 〜です |
| 〜ということになります | 〜になる / 〜です |
| 多岐にわたる | さまざまな |
