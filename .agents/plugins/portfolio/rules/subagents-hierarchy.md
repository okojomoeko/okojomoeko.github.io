# Multi-Tier Subagents Hierarchy Rules (3層サブエージェント階層協調規範)

本ルールは、Pi Coding Agent をはじめとするマルチエージェント環境において、**「司令塔モデル」「手を動かす軽量モデル」「細かいタスクをこなす超軽量モデル」** の3層モデル階層を効率的に運用するための行動規範です。

---

## 1. 3層モデル階層の役割と使い分け (Model Hierarchy)

コンテキストの肥大化を防ぎ、トークンコストを最小化しながら高品質な出力を得るため、以下の3階層でタスクを分離・委譲します。

| 階層 | 主なロール / サブエージェント | モデル定義 | 担当責務 |
| :--- | :--- | :--- | :--- |
| **Tier 1: 司令塔 / デフォルト** | 親セッション, `oracle`, `planner` | `Qwen3.8-27B-Brainwaves-2M-qx64-hi-mlx` | 全体設計、タスク分解、Meta-prompt生成、サブエージェント管理、最終統合・意思決定（最強モデル） |
| **Tier 2: 実装・軽量** | `worker`, `reviewer`, `coder` | `gemma-4-26B-A4B-it-qat-uncensored-heretic-mlx-vlm-4Bit` | コード実装、TDDテストコード作成、関数リファクタリング、差分コードレビュー（Sonnet相当・軽量） |
| **Tier 3: 探索・超軽量** | `scout`, `researcher`, `inspector` | `Ornith-1.5-9B-MLX-6bit` | ファイル探索、grep/AST調査、ログ・エラー箇所特定、ドキュメント要約（最軽量モデル） |

---

## 2. 親エージェント（司令塔）の行動原則

1. **直接の広範探索・単純コード生成の自粛**:
   - 親セッションはオーケストレーターとして振る舞い、自ら大量のファイルを直接読み込んだり長大なコードを一気に書いたりせず、サブエージェントを活用せよ。
2. **Meta-Prompt の明示**:
   - サブエージェントをディスパッチする際は、「ゴール」「対象ファイル」「満たすべき制約」「期待する出力形式」を明確に指示せよ。
3. **探索先行（Scout-First）**:
   - 実装に着手する前に、まず超軽量モデル（`scout`）を用いてコードベース内の依存関係、既存パターン、テストケースを特定せよ。
4. **実装と検証の分離（Worker & Reviewer）**:
   - コード実装は軽量モデル（`worker`）に依頼し、実装完了後は `reviewer` または親セッション自身で差分とテスト結果を厳密に検証せよ。
5. **停止問題の防止と自律完走規律 (Stopping Problem Prevention)**:
   - 自律ループやバッチ・Headless (`-p`) 実行時、サブエージェントは曖昧さを理由にユーザーや親セッションへ質問して停止（ブロック）してはならない。
   - Meta-Prompt に「質問でブロックせず、最も確からしい推論・安全なフォールバックを採用してタスクを完走させ、結果と前提条件を返却せよ」と明示せよ。
6. **ルート会話 ID 伝播と知見集約 (Root Conversation Knowledge Consolidation)**:
   - ハーネス（Antigravity v1.4.4+ 等）により MCP ツール呼び出しへ透過的に注入される `root_conversation_id` を活かし、サブエージェントで得られた事実や決定事項は `agentmemory` を通じて親セッションのコンテキストへ確実に集約せよ。

## 3. 標準的な協調ワークフロー例 (Generic Workflow)

- **探索・調査（Tier 3 Scout）**:
  - 対象モジュールの既存パーサー構造、データモデル、テストケースの配置や依存関係を調査。
- **アーキテクチャ・設計（Tier 1 Oracle）**:
  - データスキーマの選定、アルゴリズム設計、システム境界やインターフェース仕様を決定。
- **実装・テスト（Tier 2 Worker）**:
  - UIコンポーネントやビジネスロジックの実装、およびユニットテスト・結合テストの作成。
- **レビュー・検証（Tier 2 Reviewer）**:
  - 実装差分のコードレビュー、リンター・型チェック・テスト実行結果の検証。
