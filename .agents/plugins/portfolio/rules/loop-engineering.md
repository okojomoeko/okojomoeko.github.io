# Loop Engineering Guidelines (自律ループ行動規範)

自律的な開発ループ（コード生成・自己デバッグ・テスト検証の自動サイクル）を実行する際、エージェントが従うべき意思決定と安全性のルールです。

## 1. テストファースト（道徳）
*   コードベースに修正を加える前に、その修正が意図通りに動いているかを検証するためのユニットテスト、結合テスト、または検証スクリプトを用意してください。
*   テストが存在しない、または実行できない場合は、まずテストが実行できる状態に環境を整えるか、検証コードを新規に作成することを最優先タスクとします。

## 2. アトミックな検証サイクル (Atomic Verification)
*   1回の修正サイクル（1ツール実行、または1ファイルの軽微な修正）ごとに必ず検証（コンパイル、テスト実行、リンターチェック）を行ってください。
*   大量の修正を一括で行った後にテストを回すのは避けてください。自己デバッグループでの原因特定が困難になります。

## 3. 自己改ざん・プロセスキル操作の絶対禁止（メタ書き換えの制限）
*   **ルール・プロンプトの改ざん禁止**: 自身を制御しているハーネス設定ファイル（`catalog/` 以下のYAML、`AGENTS.md`、`CLAUDE.md`、システムプロンプト）を、実行中に自律的に変更または削除してはなりません。これらは「法律」であり、エージェントが書き換えることは許されません。
*   **プロセス停止コマンドの実行禁止**: 自身を起動・監視しているハーネスプロセス（親プロセス、スーパーバイザー、またはOrcaなどの実行コンテキスト）を強制終了（キル）する操作、およびシステムシャットダウン等の破壊的なOSコマンドを実行してはなりません。

## 4. 限界の自覚とエスカレーション (Surrender & Escalation)
*   **3ループ限界ルール**: 同じエラーログやテストの失敗に対し、修正アプローチを変えても解決せず3回以上ループした場合は、自ら思考とループを停止（降伏）してください。
*   **人間へのエスカレーション**: ループを停止後、これまでの試行履歴、エラーログ、仮説、そしてなぜ手詰まりになったかを整理した「エスカレーションレポート」を作成し、人間の介入を求めてください。

## 5. Anti-Pattern #1 の禁止と Maker/Checker 分離義務 (Maker/Checker Separation)
*   **自己採点の絶対禁止**: コードを作成したエージェント（Maker / Implementer）自身に完了判定（自己承認）を行わせてはなりません。確証バイアスによる甘い判定や弱体化テストの見逃し（Anti-Pattern #1）を根絶するためです。
*   **独立検証者（Checker / Verifier）の必須配備**: 検証は必ず独立した Checker ロール（`loop-verifier` スキル）が担当し、`Default stance: REJECT`（客観的証拠が揃うまで棄却）の立場でテスト実行と実証を行ってください。
*   **収束規律の厳格準拠**: Checker と Maker 間のレビュー・修正対話は、無限ループ防止のため `@rules/common/code-review.md`（3ラウンド収束規律、Diff-only再レビュー、バグクラス単位指摘）に厳格に準拠すること。

## 6. Dogfooding Walkthrough 義務 (実機起動・結合実証)
*   **単体テスト通過＝完了の誤認根絶**: 単体テスト（pytest 等）が全件パスしただけで完了と報告してはなりません。
*   **実機エントリーポイントの直接実行**: `README.md`、`package.json`、`pyproject.toml` 等に記載されたユーザー向け起動コマンド（`npm run dev`, `uvicorn ...`, `xhs probe check --walkthrough`）を実際に叩き、プロセスが正常起動し、ポート衝突がなく、API エンドポイントが HTTP 200 を返すことを自ら実証（Dogfooding）してください。検証完了後は起動したバックグラウンドプロセスを確実に終了（Teardown）させてください。

## 7. Contract-First ガバナンス (契約先行固定化)
*   **多言語・フルスタック時の契約固定化**: フロントエンドとバックエンド、あるいは複数サービスが連携するプロジェクトでは、コード実装に着手する前に環境変数、利用ポート（8000等のホスト占有ポートを避けた安全なポート）、API ルーティング契約（例: `/api/books`）を先行固定化してください。
*   **契約ドリフトの即時検知**: フロントエンドの呼び出し先とバックエンドのルーティング定義に1文字でも乖離（404 Not Found の温床）がある場合は、実装を進めずに契約定義と実装の整合性を最優先で是正してください。
