# Code Review Standards (コードレビュー行動憲法)

Anthropic Claude Code レビュープロトコルに基づく、高シグナル・収束指向のレビュー行動原則。

## 1. Verification-First (客観的実証先行)
- **自己申告の禁止**: レビュー提出時および完了報告時、「動くはず」「テストは通ったと思う」等の主観的申告を禁ずる。
- **実行結果の提示**: テスト実行ログ（Exit Code 0）、リンター/型チェック結果、または実機プローブ出力を客観的証拠として添付すること。

## 2. Review Convergence (レビュー収束規律)
エージェント同士のレビュー無限ループ（Thrashing Loop）を防止するため、以下の収束規律を厳格に順守せよ：
- **3ラウンド上限 (Round Cap)**: 同一PR/差分に対する自動修正・再レビューは最大3ラウンドとする。3回で解消しない場合は直ちに停止し、人間へエスカレーションまたは設計前提を再検討すること。
- **Diff-only 再レビュー**: 2ラウンド目以降の再レビューでは、直前ラウンドの指摘に対応して修正された新規差分のみを対象とせよ。初回に指摘しなかった未変更コードを後から蒸し返して指摘することを禁止する。
- **バグのクラス単位指摘 (Bug Class Focus)**: 同一パターンの不具合（例: 複数箇所のnull安全不備）を1行ずつ小出しに指摘するな。「〜というバグのクラス」として根本原因を指摘し、一括修正を要求せよ。
- **重複指摘の禁止**: 過去のラウンドで既に投稿済みの指摘を反復掲示すべからず。

## 3. High-Signal & Evidence-Based (高シグナル・事実立脚原則)
- **スタイル・好みの指摘排除**: コードスタイルやフォーマットの議論は静的ツール（リンター/フォーマッター）に委ねよ。個人の好みや主観的オピニオンによるブロックを禁止する。
- **証拠の絶対提示**: 指摘を行う際は、必ず該当するファイルパス、行番号、および問題の発生条件（入力と期待される動作の不一致）を客観的証拠として明記せよ。名前からの推測による指摘を禁ずる。
- **REVIEW.md への服従**: リポジトリまたはディレクトリに `REVIEW.md` が存在する場合、コードオーナーが定義した「失敗の定義（What failure looks like）」およびレビュー制約を最優先基準とせよ。
